## 1. 项目概述

### 1.1 系统目的
本项目旨在构建一个标准化的**新人入职资源准备协作平台**。系统通过将人力资源（HR）的入职需求与 IT 资产管理（MIS）的资源准备过程数字化、闭环化，解决传统流程中存在的资源漏发、资产账目混乱、账号指派不可追溯等痛点。

### 1.2 核心价值
- **闭环追踪**：实现从“入职申请 $\rightarrow$ 资源准备 $\rightarrow$ 交付确认”的全生命周期跟踪。
- **资产强一致性**：通过系统级校验，确保每件硬件资产和每个软件账号在同一时间仅被指派给一名用户，消除资产冲突。
- **协作提效**：将非结构化的沟通（邮件/IM）转变为结构化的状态机流转，减少信息同步成本。
- **合规与审计**：建立完整的资源流转日志，为未来的离职资源回收提供精准的镜像清单。

## 2. 业务分析

### 2.1 业务流程图 (Workflow)
系统采用**请求期 $\rightarrow$ 准备期 $\rightarrow$ 交付期**的三段式流程：

1. **请求期**：HR 提交《新人入职请求表单》（含岗位、入职日期、资源模板） $\rightarrow$ 系统状态：`Pending`。
2. **准备期**：MIS 接收通知 $\rightarrow$ 执行资源指派（绑定硬件 SN / 分配软件账号） $\rightarrow$ 提交就绪 $\rightarrow$ 系统状态：`Ready`。
3. **交付期**：HR 获取《资源清单》并交付新人 $\rightarrow$ 点击“确认交付” $\rightarrow$ 系统状态：`Delivered`（流程终结并存档）。

### 2.2 用户角色权限矩阵

| 功能模块 | 操作项 | HR (人力资源) | MIS (IT资产) | 权限约束 |
| :--- | :--- | :---: | :---: | :--- |
| **入职请求** | 创建/提交/修改请求 | ✅ | ❌ | 修改仅限 `Pending` 状态 |
| | 查看请求进度 | ✅ | ✅ | 全局只读 |
| **资源登记** | 软件账号指派/录入 | ❌ | ✅ | 防止非专业人员修改账号 |
| | 硬件资产绑定 | ❌ | ✅ | 必须联动资产库状态 |
| | 发布就绪通知 | ❌ | ✅ | 触发流程流转至交付阶段 |
| **交付管理** | 查看最终资源清单 | ✅ | ✅ | 权限开放，方便核对 |
| | 确认资源已交付 | ✅ | ❌ | 只有 HR 能闭环确认 |
| **系统管理** | 资源模板配置 | ❌ | ✅ | 定义岗位标准配置 |
| | 资产库基础维护 | ❌ | ✅ | 资产入库、报废管理 |

### 2.3 核心业务逻辑
- **状态机流转**：`Draft` $\rightarrow$ `Pending` $\rightarrow$ `Processing` $\rightarrow$ `Ready` $\rightarrow$ `Delivered` (或 `Cancelled`)。
- **资产绑定机制**：硬件资产绑定必须执行 $\text{Asset Status: In Stock} \rightarrow \text{In Use}$ 的原子操作。
- **资源模板化**：支持“岗位 $\rightarrow$ 资源包”映射（如：研发岗 = 笔记本 + 邮箱 + GitHub），自动生成 MIS 待办清单。

## 3. 技术方案

### 3.1 总体架构
采用**模块化单体架构 (Modular Monolith)**。在保证开发效率的同时，通过逻辑层解耦（HR 模块、MIS 模块、资产模块），确保未来可平滑演进为微服务。

### 3.2 技术栈选型

| 维度 | 选型 | 理由 | 业务支撑点 |
| :--- | :--- | :--- | :--- |
| **前端** | **Next.js + Tailwind CSS + Shadcn UI** | 全栈 React 框架 + 工业级组件库 | 快速交付专业、一致的管理后台界面 |
| **后端** | **Node.js (TS) + NestJS** | 强类型、企业级依赖注入架构 | 确保复杂状态流转的逻辑严谨性 |
| **数据库** | **PostgreSQL** | ACID 强一致性关系型数据库 | 保证资产指派的唯一性，防止重复分配 |
| **ORM** | **Prisma** | Type-safe Schema 管理 | 提高数据库迁移速度与关联查询效率 |
| **部署** | **Docker + Cloud Container** | 容器化标准部署 | 环境一致性，支持 CI/CD 自动化 |

### 3.3 核心数据模型 (Schema)
- **`Requests`**：存储入职申请主表（状态、员工信息、时间线）。
- **`Assets`**：硬件资产库（财产编号 `asset_tag`、类别、状态 `In Stock/In Use`）。
- **`Accounts`**：软件账号库（服务名称、账号 ID、加密初始密码）。
- **`ResourceAssignments`**：关联表（`RequestID` $\leftrightarrow$ `AssetID`/`AccountID`），记录谁在何时指派了什么。

### 3.4 关键技术挑战应对
- **并发冲突**：使用 PostgreSQL **行级锁 (`FOR UPDATE`)** 和数据库事务，确保同一资产不会被同时指派给两个请求。
- **数据安全**：敏感密码采用**加密存储**，交付时通过带有过期时间的 **Signed URL** 传递，并记录访问审计日志。

## 4. MVP 功能路线图

为了快速验证流程并降低交付风险，首版开发将聚焦于**“主线闭环”**，暂缓非核心自动化功能。

### 4.1 P0 核心功能 (必须在首版交付)
- **基础资产管理**：MIS 可对硬件资产进行基础的 CRUD 操作（入库/修改）。
- **请求发起流**：HR 可创建入职请求 $\rightarrow$ 状态转为 `Pending` $\rightarrow$ 状态看板实时同步。
- **资源指派流**：MIS 可在请求单内手动绑定资产/账号 $\rightarrow$ 资产状态自动联动 $\rightarrow$ 点击发布转为 `Ready`。
- **交付闭环流**：系统生成基础资源清单 $\rightarrow$ HR 确认交付 $\rightarrow$ 状态转为 `Delivered`。
- **基础权限**：实现 HR 与 MIS 的角色隔离访问控制。

### 4.2 P1 增强功能 (计划在 v1.1 迭代)
- **资源模板化**：实现“岗位 $\rightarrow$ 预设清单”的自动生成。
- **敏感信息脱敏**：实现密码掩码显示及一次性查看机制。
- **批量操作工具**：支持账号库的批量导入与快速指派。
- **审计追踪**：实现单件资产的历史流转时间轴查询。

### 4.3 验收标准 (AC)
- **核心路径验证**：一名 HR 提交请求 $\rightarrow$ 一名 MIS 完成指派 $\rightarrow$ 该 HR 确认交付，全过程状态流转无误。
- **并发校验**：尝试将同一资产编号指派给两个不同的请求，系统必须拦截并报错。
- **数据完整性**：确认交付后，关联资产的状态必须且仅为 `In Use`。
