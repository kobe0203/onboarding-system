# 🚀 “新人入职资产领用系统” MVP 功能清单

## 1. HR 模块：需求发起与交付闭环
*目标：让 HR 能够快速下单，并清晰地知道“东西准备好了没”。*

| 功能点 | 描述 | 优先级 | 验收标准 (AC) |
| :--- | :--- | :--- | :--- |
| **创建入职请求单** | 输入新人基本信息（姓名、部门、岗位、入职日期）并提交。 | **P0** | 提交后生成唯一单号，状态变为 `待指派`。 |
| **岗位模板联动** | 选择岗位后，系统自动加载预设的资产清单（如：研发 $\rightarrow$ Mac+VPN）。 | **P0** | HR 无需手动勾选设备，减少漏选风险。 |
| **入职单状态看板** | 列表页查看所有单据的实时状态（待处理 $\rightarrow$ 配置中 $\rightarrow$ 已就绪）。 | **P0** | 状态颜色区分，支持按入职日期排序。 |
| **标记交付完成** | 对 `已就绪` 的单据点击“确认交付”。 | **P0** | 状态变更为 `已交付`，触发资产状态变更。 |
| **交付清单导出** | 一键生成该新人的账号/设备清单 PDF 或 网页快照。 | **P1** | 方便 HR 直接打印或发送给新人。 |

## 2. MIS 模块：资产配置与出库
*目标：消除手动录入的混乱，确保资产绑定准确。*

| 功能点 | 描述 | 优先级 | 验收标准 (AC) |
| :--- | :--- | :--- | :--- |
| **任务认领机制** | MIS 在 `待指派` 列表中点击“认领”某单据。 | **P0** | 认领后单据绑定至该 MIS，状态变为 `配置中`。 |
| **软资产录入** | 在单据中填写具体账号、初始密码、权限范围。 | **P0** | 所有模板要求的软件项必须填完才能提交。 |
| **硬资产绑定** | 从资产库下拉选择具体设备 $\rightarrow$ 自动填充财编/序列号。 | **P0** | 禁止手动输入财编，必须选择库内可用资产。 |
| **就绪提交** | 点击“提交就绪”，通知 HR 可进行物理交付。 | **P0** | 状态变更为 `已就绪`。 |
| **异常驳回** | 发现 HR 信息错误时，可将单据驳回至 HR 修改。 | **P1** | 需填写驳回理由，状态回滚至 `待指派/待修改`。 |

## 3. 基础模块：资产库与权限管理
*目标：建立单一事实来源 (Single Source of Truth)，防止资产状态冲突。*

| 功能点 | 描述 | 优先级 | 验收标准 (AC) |
| :--- | :--- | :--- | :--- |
| **极简资产库** | 维护硬件清单（设备名、型号、财编、状态：可用/占用/报废）。 | **P0** | 支持简单的 CSV 导入，方便初始化数据。 |
| **状态同步逻辑** | 硬件被绑定 $\rightarrow$ `占用`；HR 确认交付 $\rightarrow$ `使用中`。 | **P0** | 资产状态必须与单据状态强联动，防止重复指派。 |
| **角色权限控制** | 定义 HR 角色（仅限发起和确认）和 MIS 角色（仅限配置和管理库）。 | **P0** | 登录后根据角色进入不同的主界面。 |
| **资产水位看板** | 简单统计：当前可用笔记本数量、显示器数量等。 | **P1** | 预警机制：当可用数 $< 3$ 时，数值显示为红色。 |
| **简单审计日志** | 记录单据状态变更的时间戳和操作人。 | **P1** | 能够追溯“谁在什么时候把单据改为已就绪”。 |

## 🛠 Sprint 排序师的执行建议

### 1. 砍掉的部分（V1 绝对不做）
- **自动指派系统**：不要写算法，先用“手动认领”，验证流程是否跑通。
- **与 HR 系统的 API 对接**：先用手动创建单据，不要在 V1 浪费时间在第三方接口联调上。
- **复杂的审批流**：入职领用通常是行政指令，不需要多级审批，直接触发即可。

### 2. 关键路径 (Critical Path)
**HR 创建 $\rightarrow$ MIS 认领 $\rightarrow$ 绑定资产 $\rightarrow$ HR 确认交付 $\rightarrow$ 资产库状态更新。**
这个链路是 MVP 的生命线，所有 P0 功能必须优先围绕这个闭环开发。

### 3. 风险预警
- **数据污染**：如果资产库初始数据不准，整个系统就是垃圾。建议在上线前，由 MIS 完成一次全量盘点并导入。
- **并发冲突**：两个 MIS 同时抢一个笔记本怎么处理？（建议：在点击“绑定”时再次校验资产状态）。
