# 新人入职资产管理系统设计规格书 (Design Specification)

**版本：** v1.0  
**状态：** 草案/评审中  
**文档目标：** 定义一套用于管理新人入职软硬件资产领用的闭环系统，解决信息不对称、交付时效低下及资产追溯困难等痛点。

---

## 1. 项目概述

### 1.1 系统目标
本系统旨在构建一个从 **HR 需求触发 $\rightarrow$ MIS 配置执行 $\rightarrow$ HR 最终交付** 的标准化资产领用全生命周期管理平台。系统将通过标准化的岗位模板、严格的状态流转机制和强一致性的资产库，确保每一位入职员工在入职首日能够准时、完整地获得所有必要的办公设备和软件权限。

### 1.2 核心价值
- **消除信息差**：通过数字化单据替代口头或邮件沟通，明确交付物清单。
- **提高交付时效**：通过状态看板实时跟踪进度，预警潜在的交付风险。
- **资产可追溯**：实现硬件财产编号与人员的强绑定，确保资产流向清晰。

## 2. 需求分析

### 2.1 用户角色定义 (User Personas)

| 角色 | 核心目标 | 关注点 (KPI/Pain Points) |
| :--- | :--- | :--- |
| **HR (人力资源)** | 确保新人入职第一天“顺畅启动” | **交付及时性**。避免被新人询问账号状态，减少与 IT 部门的重复沟通。 |
| **MIS (IT/运维)** | 高效、准确地配置资产且可追溯 | **操作效率与资产准确率**。一次性获取完整需求，避免反复确认，确保出库有据可查。 |
| **管理员 (Admin)** | 资产池管理与审计 | **资产水位线**。库存是否充足？资产分布情况如何？流程瓶颈在哪里？ |

### 2.2 业务流程图 (Business Process Flow)
系统将流程分为三个关键阶段：**触发期 $\rightarrow$ 配置期 $\rightarrow$ 交付期**。

1. **触发期 (HR)**：创建入职单 $\rightarrow$ 系统基于岗位模板自动生成资产清单 $\rightarrow$ 状态：`待指派`。
2. **配置期 (MIS)**：认领任务 $\rightarrow$ 配置软资产（账号/权限） $\rightarrow$ 绑定硬资产（财编/序列号） $\rightarrow$ 状态：`配置中` $\rightarrow$ 提交就绪 $\rightarrow$ 状态：`已就绪`。
3. **交付期 (HR)**：将物理资产与账号清单交付新人 $\rightarrow$ 点击确认交付 $\rightarrow$ 状态：`已交付`。

### 2.3 核心业务逻辑

#### A. 状态流转模型 (State Machine)
| 当前状态 | 触发动作 | 执行人 | 目标状态 | 核心约束/校验 |
| :--- | :--- | :--- | :--- | :--- |
| **(Start)** | 创建入职单 $\rightarrow$ 提交 | HR | **待指派** | 必须填写入职日期 $\le$ 交付日期 |
| **待指派** | 认领任务 / 系统自动指派 | MIS | **配置中** | 认领后单据锁定，不可被重复认领 |
| **配置中** | 填写所有必填资产 $\rightarrow$ 提交 | MIS | **已就绪** | 校验：所有标准清单项必须有值 |
| **已就绪** | 点击“确认交付” | HR | **已交付** | 触发资产库状态更新为 `In Use` $\rightarrow$ 绑定至新人 |

#### B. 关键逻辑细节
- **标准清单逻辑**：预设 `岗位模板` $\rightarrow$ `资产清单`（例如：研发岗 $\rightarrow$ MacBook Pro + Gitlab + VPN）。
- **资产联动逻辑**：硬件选择必须从资产库下拉选择，禁止手动输入。选择后立即变更资产状态为 `占用中`。
- **安全性**：账号密码在 `配置中` 状态可见，`已交付` 后进行掩码处理或强制引导新人修改。

## 3. 技术架构方案

### 3.1 技术栈选型

| 维度 | 选型 | 理由 |
| :--- | :--- | :--- |
| **前端** | Next.js + TS + Tailwind CSS + Shadcn UI | 利用 App Router 处理 RBAC 权限；Shadcn UI 提供高度可定制的表单界面。 |
| **后端** | Node.js (TypeScript) + NestJS | 模块化架构支持领域隔离（Form/Asset/Auth）；全栈 TS 确保 DTO 类型统一。 |
| **数据库** | PostgreSQL 15+ + Prisma | 强一致性保证资产不丢失；JSONB 字段支持动态表单数据的灵活性。 |
| **加密** | AES-256-GCM | 针对敏感资产（API Key/密码）采用对称加密存储，密钥存储于环境变量/Vault。 |

### 3.2 关键设计点
- **RBAC 权限模型**：通过 Next.js Middleware 实现基于角色的页面拦截。
- **动态表单存储**：使用 PostgreSQL 的 `JSONB` 类型存储不同岗位所需的差异化资产字段。
- **审计日志 (Audit Log)**：建立专用表记录 `UserID $\rightarrow$ OldValue $\rightarrow$ NewValue $\rightarrow$ Timestamp`，确保资产变更全链路可追溯。

## 4. MVP 功能清单

### 4.1 P0 (Must-have)：核心闭环
- **HR 模块**：创建入职请求单、岗位模板联动、状态看板、标记交付完成。
- **MIS 模块**：任务认领机制、软资产录入、硬资产库绑定（禁止手动输入）、就绪提交。
- **基础模块**：极简资产库（CSV 导入）、状态同步逻辑（可用 $\rightarrow$ 占用 $\rightarrow$ 使用中）、基础 RBAC 权限控制。

### 4.2 P1 (Nice-to-have)：体验优化
- **HR 模块**：交付清单一键导出 PDF。
- **MIS 模块**：异常驳回机制（含理由填写）。
- **基础模块**：资产水位预警看板（数量 $< 3$ 时标红）、详细审计日志记录。

## 5. 交付里程碑

项目将分为四个阶段迭代，确保在每个阶段均有可验证的产出。

### 阶段 1：基础框架与数据模型 (Foundation)
- **目标**：搭建开发环境，建立数据库 Schema。
- **交付物**：
    - 基础前后端骨架。
    - 资产库基础表、用户权限表、入职单表。
    - 资产库 CSV 导入功能。

### 阶段 2：核心业务流转 (Core Workflow)
- **目标**：实现从 HR 发起到 MIS 配置的完整链路。
- **交付物**：
    - HR 创建单据 $\rightarrow$ 岗位模板触发逻辑。
    - MIS 认领 $\rightarrow$ 绑定资产 $\rightarrow$ 提交就绪流转。
    - 基础的状态看板。

### 阶段 3：权限、安全与闭环 (Security & Closing)
- **目标**：完善权限控制，实现最终交付闭环。
- **交付物**：
    - 基于角色的访问控制 (RBAC) 实施。
    - 敏感信息 AES-256-GCM 加密存储方案。
    - HR 确认交付 $\rightarrow$ 资产状态最终变更逻辑。

### 阶段 4：测试、优化与发布 (QA & Release)
- **目标**：消除 Bug，提升用户体验，正式上线。
- **交付物**：
    - 全链路集成测试报告。
    - P1 级功能（PDF 导出、水位预警）上线。
    - 部署至生产环境。
